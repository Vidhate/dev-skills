# Explore Repo

You are about to explore the current repository using three parallel subagents. Each agent has a single focused question. Their job is **data gathering only** — no formatting, no visualization. After all three return, you (the skill) own the rendering step entirely.

## Step 1: Launch three Explore subagents in parallel

Fire all three at the same time (in a single response, as parallel tool calls):

**Agent 1 — Entry Points**
```
Search this codebase for the main execution entry points. Look for files named main, index, app, server, cmd, or similar top-level runners. Identify the primary entry file(s) and describe the top-level execution path in 2–3 sentences. Return raw findings only: file paths and plain-text descriptions. No formatting.
```

**Agent 2 — Data Models & Domain**
```
Search this codebase for the core data models, types, interfaces, and schemas that define the domain. Look in files named types, models, schema, entities, interfaces, or similar. List the 5–10 most important domain concepts with a one-line description of each and the file path where they are defined. Return raw findings only: names, descriptions, file paths. No formatting.
```

**Agent 3 — Tech Stack & Dependencies**
```
Read the dependency manifest(s) in this repo (package.json, requirements.txt, go.mod, Cargo.toml, pom.xml, build.gradle, Gemfile, or equivalent). Identify the runtime language and version, the top 5–10 most significant external dependencies and their purpose, the test framework, build tool, and any deployment config present. Return raw findings only: plain lists of names and one-line purposes. No formatting.
```

## Step 2: Render CODEBASE.html

Once all three agents have returned, write a `CODEBASE.html` file at the root of the repo. You are fully responsible for the visual design. Use the layout and style rules below exactly.

### Visual design rules

- **Self-contained** — single HTML file, no external dependencies, all CSS and JS inline.
- **Color palette** — dark background `#0d1117`, card surfaces `#161b22`, borders `#30363d`, primary accent `#58a6ff`, secondary accent `#3fb950`, muted text `#8b949e`, body text `#e6edf3`.
- **Typography** — system font stack: `-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`. Code/paths in `monospace`.
- **Layout** — full-width header banner with repo name and one-sentence summary. Below it, a **3-column card grid** (entry points | domain model | tech stack), each card with a colored top border accent. Below the grid, a full-width "Where to Start" strip.
- **Entry Points card** — for each entry file, show the filename as a monospace pill badge, followed by the description as body text. Use the `#58a6ff` accent border.
- **Domain Model card** — render each entity as a row: entity name in bold + file path in muted monospace + one-line description. Use the `#3fb950` accent border.
- **Tech Stack card** — two sections separated by a thin divider: (1) a small "stack pill" row for language, framework, test tool, build tool; (2) a dependency list with name in monospace and purpose in muted text. Use a `#e3b341` accent border.
- **Where to Start strip** — numbered list (1, 2, 3) of recommended first-read files. Each item: file path in a monospace badge + one sentence on why to read it first.
- **Footer** — muted text: `Generated by /explore-repo · {DATE}`.
- **No external fonts, no CDN links, no images.** Pure HTML + inline CSS only.
- Keep the file under 300 lines. Prioritize clarity over decoration.

### Content mapping

| Section | Source |
|---------|--------|
| Repo name | Infer from root folder name or manifest `name` field |
| One-sentence summary | Synthesize from Agent 1 + Agent 2 findings |
| Entry Points card | Agent 1 findings |
| Domain Model card | Agent 2 findings |
| Tech Stack card | Agent 3 findings |
| Where to Start | Your synthesis across all three agents |
