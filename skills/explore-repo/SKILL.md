# Explore Repo

You are the coordinator. Your only direct actions are creating the `.codebase/` directory and firing subagents in sequence. You do not write any other files yourself.

## Step 0: Create output directory

Run `mkdir -p .codebase` to ensure the output directory exists before any agents fire.

---

## Step 1: Launch three parallel agents

Fire all three simultaneously. These are general-purpose agents — they need both read AND write access to explore the codebase and persist their findings. Each agent writes its own `.md` file to `.codebase/` and returns a compact summary to you (paths only — not the full data).

---

**Agent 1 — Entry Points & Core Files**

```
You are exploring a codebase. You have two responsibilities: explore thoroughly, then write your findings to disk.

EXPLORATION TASK:
Search this codebase for:
(a) The main execution entry points — files named main, index, app, server, cmd, or similar top-level runners. Read the entry files themselves, not just their names. Trace what they import and invoke.
(b) The 4–6 most important files a new developer should read to understand core functionality — where the most meaningful business logic, algorithms, or key abstractions live.

FINDINGS FORMAT — structure your findings exactly as below:

ENTRY_POINTS:
- path: <file path>
  description: <one sentence on what this file does>
  key_lines:
    - line: <line number>
      reason: <why this line is significant>

CORE_FILES:
- path: <file path>
  why: <one sentence on what core concept this file illuminates>
  look_for: <one sentence on what to look for inside it>
  key_lines:
    - line: <line number>
      reason: <why this line is significant>

NOTES:
<3–5 sentences of dense prose: overall execution flow, architectural patterns, anything surprising or important. This is source-of-truth context for diagram generation — be specific.>

WRITE TASK:
Write your complete findings to `.codebase/1-entry-points.md`. Prepend this header line:
`# Entry Points & Core Files — generated by /explore-repo`

RETURN to the coordinator: only the list of file paths from ENTRY_POINTS and CORE_FILES — nothing else.
```

---

**Agent 2 — Domain Models**

```
You are exploring a codebase. You have two responsibilities: explore thoroughly, then write your findings to disk.

EXPLORATION TASK:
Search for the core data models, types, interfaces, schemas, and entities that define the domain. Look in files named types, models, schema, entities, interfaces, or similar. Find the 5–10 most important domain concepts. Read each definition fully and extract its fields.

FINDINGS FORMAT — structure your findings exactly as below:

MODELS:
- name: <EntityName>
  file: <file path>
  description: <one sentence on what this entity represents>
  key_lines:
    - line: <line number>
      reason: <why this line is significant>
  fields:
    - name: <field name>
      type: <field type>
      note: <optional — one short phrase if the field needs explanation>
  relationships:
    - target: <OtherEntityName>
      label: <short verb phrase, e.g. "has many", "belongs to", "references">

NOTES:
<3–5 sentences of dense prose: the domain model as a whole, core business concepts, how entities relate at a high level, any patterns evident (event sourcing, CQRS, normalisation strategy). Be specific — this is source-of-truth context for diagram generation.>

WRITE TASK:
Write your complete findings to `.codebase/2-domain-models.md`. Prepend this header line:
`# Domain Models — generated by /explore-repo`

RETURN to the coordinator: only the list of file paths from MODELS — nothing else.
```

**Agent 3 — Tech Stack**

```
You are exploring a codebase. You have two responsibilities: explore thoroughly, then write your findings to disk.

EXPLORATION TASK:
Read the dependency manifest(s) in this repo (package.json, requirements.txt, go.mod, Cargo.toml, pom.xml, build.gradle, Gemfile, or equivalent). Also look for config files (Dockerfile, .env.example, CI config, deployment manifests).

FINDINGS FORMAT — structure your findings exactly as below:

STACK:
  language: <name and version>

  test_runner: <test tool>
  build_tool: <build tool>
  deploy_config: <dockerfile / k8s / serverless / none>

DEPENDENCIES:
- name: <package name>
  purpose: <one short phrase>

NOTES:
<2–3 sentences: overall technology choices, why this stack suits the apparent use case, any tooling that would affect a new developer's setup.>

WRITE TASK:
Write your complete findings to `.codebase/3-tech-stack.md`. Prepend this header line:
`# Tech Stack & Dependencies — generated by /explore-repo`

RETURN to the coordinator: only the STACK block — nothing else.
```

## Step 2: Launch the File Explorer agent

Once Agents 1 and 2 have returned their path lists, fire this agent and pass the collected paths into the prompt:

---

**Agent 4 — File Explorer**

```
You are gathering raw data for an IDE-style file explorer. You have two responsibilities: collect the data, then write it to disk.

The following files have been identified as critical:
<critical_files>
{LIST ALL UNIQUE FILE PATHS RETURNED BY AGENTS 1 AND 2, ONE PER LINE}
</critical_files>

Annotations from exploration:
<key_lines>
{PASTE ALL key_lines DATA FROM AGENTS 1 AND 2, GROUPED BY FILE PATH}
</key_lines>

EXPLORATION TASKS:

TASK A — Full directory tree:
Walk the entire repository. Exclude: .git, node_modules, __pycache__, .venv, venv, dist, build, .next, coverage, .codebase. Return as indented text (2 spaces per level), directories before files within each level:

DIRECTORY_TREE:
src/
  api/
    routes.py
  models/
    user.py
main.py

TASK B — Critical file contents:
For each file in <critical_files>, read and return its contents verbatim — character for character, exactly as on disk. Do not paraphrase or regenerate. Truncate at 600 lines with "... [truncated at 600 lines]" if needed.

FILE_CONTENT:
path: <file path>
---
<exact file contents>
---

TASK C — Confirm annotations:
For each critical file, confirm the line numbers from <key_lines> are accurate against the actual file contents you just read. Correct any line numbers that are off. Return the verified annotations grouped by file path.

WRITE TASK:
Write your complete findings (DIRECTORY_TREE + all FILE_CONTENT blocks + verified annotations) to `.codebase/4-file-explorer.md`. Prepend this header:
`# File Explorer Data — generated by /explore-repo`

RETURN to the coordinator: confirm the file was written. Nothing else.
```

## Step 3: Launch the Renderer agent

Once Agent 4 has confirmed its file is written, fire this agent. Pass nothing in the prompt — it reads everything it needs from disk.

---

**Agent 5 — Renderer**

```
You are a rendering agent. Your only job is to write `.codebase/index.html`. Read what you need from disk. Do not explain or summarise your work — just write the file and stop.

STEP 1 — Read your source data:
Read all of these files from disk before generating any HTML:
- `.codebase/1-entry-points.md`
- `.codebase/2-domain-models.md`
- `.codebase/3-tech-stack.md`
- `.codebase/4-file-explorer.md`

Also attempt to read `./DESIGN.md` from the repo root:
- Found and has content → use it as your primary design guide (colors, typography, tone, layout) for both tabs.
- Not found or empty → use the default design spec below. This is the common case — not an error.

STEP 2 — Write `.codebase/index.html`:

## Default design spec

- Color palette: dark background `#0d1117`, card surfaces `#161b22`, borders `#30363d`, primary accent `#58a6ff`, secondary accent `#3fb950`, muted text `#8b949e`, body text `#e6edf3`, amber `#e3b341`, highlight yellow `#f0e68c22`.
- Typography: `-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`. File paths and code in monospace.
- Mermaid.js via CDN: `https://cdn.jsdelivr.net/npm/mermaid/dist/mermaid.min.js`. Everything else: pure inline CSS + JS, no other external dependencies.

## Global structure: two tabs

Fixed tab bar at the top. Two tabs: **Overview** and **Explorer**. Switching shows/hides the corresponding `<div>` — no page reload. Active tab has primary accent underline.

## Tab 1: Overview

**Header** — repo name (large) + one-sentence summary (synthesised from NOTES in files 1 and 2). Right side: tech stack pills (language, framework, test runner, build tool, deploy) as small rounded badge tags.

**Two-column body:**
- Left (40%) — Entry Points panel, `#58a6ff` top border. Each entry point: monospace path pill + description.
- Right (60%) — Domain Model panel, `#3fb950` top border.
  - Live search/filter input at top (case-insensitive, real-time).
  - Each model: clickable accordion card. Collapsed: name + file path (muted) + description + chevron. Expanded: fields table (Field / Type / Note, row striping) + relationships as muted italic lines. One open at a time, smooth max-height transition 200ms.

**Diagrams section** — full-width, `#161b22` bg, `#58a6ff` top border. Title: "Relationships & Dependencies". Use the NOTES prose from files 1 and 2 as source of truth for actual relationships — not just the structured fields. Render two Mermaid diagrams side by side:
1. Domain model relationships — `graph LR` or `erDiagram`. Only draw explicitly stated edges.
2. Execution flow — `graph TD` from entry points through key services and models. Max 8–12 nodes. Use NOTES for accuracy.
Initialise: `mermaid.initialize({ startOnLoad: true, theme: 'dark' })`. Omit a diagram if data is insufficient rather than drawing a trivial one.

**Where to Start** — full-width, `#161b22` bg, `#e3b341` top border. Numbered list from CORE_FILES. Each: amber number badge + path badge (click-to-copy, "Copied!" tooltip) + `why` + `look_for` in muted italic below.

**Footer** — `Generated by /explore-repo · {DATE}`.

## Tab 2: Explorer

Full-height split pane below the tab bar.

**Left pane (25%, scrollable)** — file tree from DIRECTORY_TREE in `4-file-explorer.md`.
- All directories start expanded, collapsible via ▶/▼ toggle.
- Each file is clickable — loads content into right pane.
- Critical files (those with FILE_CONTENT entries) get a colored dot by category: entry point → `#58a6ff`, domain model → `#3fb950`, core file → `#e3b341`. Highest priority dot wins if multiple apply.
- Non-critical files: shown without dot, click shows "Content not pre-loaded" placeholder.

**Right pane (75%, scrollable)** — file content viewer.
- Default: "Select a file from the tree to view its contents."
- Critical file selected: file path header + verbatim contents from FILE_CONTENT (character-perfect, no regeneration) + line number gutter + highlighted lines from annotations (`#f0e68c22` bg, hover tooltip showing reason).
- Non-critical file selected: file path header + "Content not pre-loaded. Open this file in your editor." + click-to-copy path.
- Content in `<pre>`, `white-space: pre`, `overflow-x: auto`. Line gutter and content scroll together.

All JS inline. No libraries except Mermaid (Tab 1 only). File tree collapse state persists within the tab session.
```

## Step 4: Launch the Synthesis agent

Once the Renderer confirms `index.html` is written, fire this agent:

---

**Agent 6 — Synthesis**

```
You are a synthesis agent. Read the exploration files from disk and write a comprehensive `exploration-summary.md` that serves as the definitive index and narrative summary of this entire codebase exploration.

READ these files first:
- `.codebase/1-entry-points.md`
- `.codebase/2-domain-models.md`
- `.codebase/3-tech-stack.md`
- `.codebase/4-file-explorer.md`

Then write `.codebase/exploration-summary.md` with the following structure:

# Codebase Exploration Summary
> Generated by /explore-repo · {DATE}

## What This Repo Does
<2–3 sentences synthesising the purpose and function of this codebase from all exploration data.>

## Architecture Overview
<4–6 sentences describing the overall architecture — how the pieces fit together, the execution flow, key design patterns, and anything a new developer must understand before touching the code.>

## Domain Model
<Prose summary of the domain — the core entities, what they represent, and how they relate. Should read as a coherent narrative, not a list.>

## Tech Stack
<One paragraph covering language, framework, key dependencies, test tooling, and anything notable about the setup.>

## Files in This Directory

| File | What it contains | When to use it |
|---|---|---|
| `1-entry-points.md` | Execution entry points, core files, key line annotations, architectural notes | Understanding how the app starts and flows |
| `2-domain-models.md` | All domain entities, fields, types, relationships, domain notes | Understanding data structures and business concepts |
| `3-tech-stack.md` | Language, framework, dependencies, tooling | Setting up dev environment or evaluating the stack |
| `4-file-explorer.md` | Full directory tree, verbatim contents of critical files, verified line annotations | Reading actual source of key files |
| `index.html` | Interactive visual — Overview tab (entry points, models, Mermaid diagrams) + Explorer tab (annotated IDE view) | Quick visual orientation, open in a browser |
| `exploration-summary.md` | This file — narrative summary + file index | Starting point for any future session |

## Using This in a Future Claude Code Session
> Read `.codebase/exploration-summary.md` and the files it references before we start. This gives you full context about this codebase without re-running the exploration.
```
