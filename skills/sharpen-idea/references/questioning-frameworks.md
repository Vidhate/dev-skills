# Questioning Frameworks

When an uncertainty is judgment-only, you ask the user a question. The quality of
that question is most of the value of this skill. A good question drives a
*distinct* new piece of clarity. A bad one circles, flatters, or asks what the web
should answer.

## One question per message

Always. Never stack questions. The user needs room to think out loud. If a topic
has layers, ask the first layer, integrate the answer, then ask the next. This is
non-negotiable — it's what makes the dialogue feel like thinking, not an intake
form.

## The four probe types

Every question should be deliberately one of these. Rotate them — don't keep
probing the same dimension. Each unlocks a different kind of clarity.

| Probe | Asks | Example |
|---|---|---|
| **Assumptions** | What are you taking for granted? | "You're assuming people already know they have this problem — what makes you confident they feel it consciously?" |
| **Evidence** | Where did this belief come from? | "What have you actually seen that tells you this is wanted, versus what you'd expect to be wanted?" |
| **Implications** | If true, what follows? If false, what breaks? | "If this works, what becomes possible that isn't today? And if the core bet is wrong, how early would you find out?" |
| **Alternatives** | What other framings or paths exist? | "Is building it the only way to test this, or is there a cheaper way to learn the same thing?" |

## Funnel technique

Move broad → narrow. Open with a framing question that gives the user room, then
narrow with each follow-up toward something specific and decidable.

```
Broad:    "What's the core thing you're betting on here?"
Narrower: "Of those, which one would you be most upset to be wrong about?"
Specific: "What would you need to see in the next two weeks to trust that bet?"
```

Don't start specific — you'll constrain the user's thinking before they've spread
out. Don't stay broad — vague questions get vague answers and conviction doesn't
move.

## Socratic sparring (use with the pushback policy)

You are a sparring partner, not an interrogator and not a yes-man:

- **Surface hidden assumptions and name them directly.** "I think there's an
  unstated assumption here that X. Is that load-bearing for you?"
- **Offer genuine counterarguments**, including uncomfortable ones — but in
  service of the user's thinking, not to win.
- **Play devil's advocate with intellectual honesty.** If you argue a side, say
  you're doing it: "Let me push the strongest version of the opposite case…"
- **Default to neutral wording.** Leading questions get you the answer you
  telegraphed, which is worthless for calibrating real conviction.

## Question hygiene

- **Open-ended** ("how", "what", "why") over yes/no. Yes/no stalls the stream.
- **Follow vague answers down.** A one-sentence answer to a big question means
  you found a soft spot — probe the "why" behind it.
- **Don't ask what you can look up.** That's a fact-checkable uncertainty; send it
  to the web instead of taxing the user.
- **Mirror, then sharpen.** Reflect what you heard in one phrase before the next
  question, so the user feels understood and you confirm you got it.
